# Q32: Quantity parsing is a separate statistical step

Date: 2026-11-15 · Internet access: yes for the first half of the round, then stopped · Status: partly complete; no accuracy figure for this project.

## 1. Conclusion

Numeric token extraction, XBRL concept tagging and QA accuracy are different targets, and their scores cannot be mixed. P2 needs the whole tuple (value, unit, scale, sign, period, comparison baseline, entity) to be correct, and the numbers must be removed from the text side channel. iXBRL can provide structured verification information, but its tags are not proof that a financial fact is absolutely correct. There is currently no evidence that this project's parsing accuracy exceeds any threshold.

## 4. Minimal viable test

List in advance: negative numbers in parentheses, bps, percent/percentage points, multiples, thousands/millions/billions, currency, fiscal year, inherited table headers, restatements, negative base periods and zero denominators. Use the whole tuple being fully correct as the main metric, and report each error type, the abstention rate and the coverage separately. Abstained items must not be quietly removed from the denominator of the overall error rate; the risk conditional on acceptance can be reported in addition, but it needs independent calibration.

Sample uniformly without replacement from a fixed finite document collection and audit the number of errors with a hypergeometric bound; use the exact binomial upper bound only if i.i.d. binary errors are assumed. For clustered reporting, the sampling unit must be defined first; thousands of figures from the same filing cannot be treated as independent trials. If we only know that the parsing failure probability is ≤ε and the structural guarantee holds when parsing is correct, then the failure probability of the corresponding end-to-end property increases by at most ε; this does not mean every sample is correct, nor does it directly give a small numeric error under incorrect parsing.

To give a small bound on |Δq|, one must additionally prove that the size of parsing errors is bounded, or output a confidence set and take the worst-case bound over all feasible parses. Order-of-magnitude misreadings can cause huge or unknown perturbations and cannot be hidden behind average accuracy.

## 5. Veto conditions

If whole-tuple errors still dominate the results across all obtainable text and cannot be controlled by abstention or an interval representation, stop claiming an end-to-end certificate. If the source of automatic labels shares an error mechanism with the parser, add independent manual verification.

## 6. Uncertainties

We did not access SEC files, did not run an extraction evaluation, did not compare all the latest LLM/rule-based tools, and did not verify coverage on real text. The original TAT-QA / FiNER scores cannot replace this project's tuple accuracy; this round reports no proxy figures.

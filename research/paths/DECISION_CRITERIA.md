# Rejection rules for the next round: what counts as worth continuing, fixed before the comparison

Date: 2026-11-15. Status: **a pre-registered proposal for the next round; not executed, has not passed G0/G1, and is not a threshold Fable has agreed to.** This page was added because the independent review pointed out that the candidates lacked concrete usefulness thresholds. The existing theory and numeric examples had been seen long before, so this page cannot be retroactively treated as their ex ante rules.

Mathematical correctness has no pass rate that "tolerates a few failures". Any counterexample to a coverage/containment claim under the stated premises requires fixing the proof, narrowing the theorem, or dropping the claim. Finite tests that find no counterexample only validate the implementation over the range tested. By contrast, the .10, 20%, 50%, and similar numbers below are **researcher choices** for allocating small-trial resources, not mathematical constants, industry standards, or literature conclusions.

## Gates common to all paths

1. First fix the target quantity, data units, test documents/events, assumptions, rejection rules, and the strongest simple baseline; exploration data cannot then serve as an independent confirmation set.
2. Write down the precise difference that explains "why existing methods are insufficient". If it is only a chaining of known tools, the result is filed as a reproduction, a conditional interface, or an application, and is not upgraded to original theory.
3. When there is no decidable evidence for a real premise, keep it as unknown. Do not count "no error found" as the audit being correct, and do not mix up the numbers of documents, paragraphs, and independent clusters.
4. An improvement must be aligned on the same target quantity, input information, failure budget, and resources. When a comparator cannot be solved, a verifiable safe bound and the solver gap must be given; one cannot pick a weak algorithm to manufacture an advantage.
5. A mathematical direction can be worth continuing because of one general boundary/impossibility result, even if the model is not more accurate; but the class it applies to and the difference from precedents must be explicit. One hand-made success point is not enough, and a general rejection cannot rest on one hand-made failure point either.

## Per-path admission rules for small trials

| Path | Object fixed first | Proposed usefulness gate | What to do if not met |
|---|---|---|---|
| 01 Complete information-set certificate | Fixed test-set accuracy as primary; macro-F1 secondary; real historicity accepted separately | Conditional deletion-statistic interval width ≤ .10, tolerating at least 1 contaminated periphery document; to claim an informative task conclusion, its lower end should exceed a constant-prediction baseline pre-specified on the same test set. Compare task utility and total cost with core-only; do not compare interval width alone | .10 is only an initial screen to exclude demos that are too wide. If not met, first decompose the cause into four parts: sources, audit, vote margin, solver relaxation. When historicity lacks evidence, the name must not be upgraded. A drop in small-head accuracy does not by itself reject; report the utility–certificate cost |
| 03 Audit-cost branch | Fixed alpha=.05, accuracy width target w=.10; a set of influence-graph families listed in advance | Under exactly the same validity conditions, relative to the strongest computable fixed design, at least one pre-specified non-degenerate structure family has a cost reduction ≥20%, with a general structural explanation or a matching lower bound; all other families and the solver costs reported as they are | 20% is a screening line for whether extra implementation complexity is worth it. If only a few small matrices benefit, or there is only a renaming, keep it as a P1 tool and do not promote it to an independent topic; meeting the line also does not mean originality |
| 02 Parsing and sensitivity | Containment event for the complete semantic tuple, fixed acceptance rule; separate the direction task from the probability-prediction task | On held-out documents, target acceptance rate ≥50%; target upper bound on certificate failure risk for accepted samples ≤5% (95% audit confidence); target for the 90th percentile, over the accepted set, of the maximum width of the per-coordinate probability intervals ≤.10. Compare coverage at the same risk/width against the rule system | First check whether the label is just a threshold rule: if so, removing the learned head is the main result, and it cannot be saved by meeting the numeric gate. If no applicable sampling design can be set up for the risk upper bound, the gate is marked unknown and cannot be passed on empirical zero errors |
| 04 Deployment tail risk | First fix beta=.95, alpha=.05, the composition of future random batches, and the estimable constraints | First check whether the identification limit is <B; the exploratory gate for practical deployment use is an upper bound ≤.8B. First compare with the exact same-constraint oracle, separating estimation cost from structural cost; common-shock/drift counterexamples must be included | .8B is only to avoid treating a tiny tightening as sufficient progress; it does not equal acceptable business risk. If the .95 tail is infeasible, only a separate sensitivity analysis over beta may be set up; one cannot lower beta after the fact and then claim the original target succeeded |
| 05 Verifiable numeric programs | Fixed question grammar, a specification for deciding real facts/correct programs, an acceptance rule | Likewise first set acceptance rate ≥50% and an upper bound on semantic/answer error risk for accepted samples ≤5% (95% audit confidence); exact-fact tasks require exact answers; interval tasks require normalized width ≤.10 on a scale declared in advance | Passing type/arithmetic checks with a semantic error still counts as a failure. If rule + calculator reaches equal or better risk–coverage–width, do not expand the language proposer; the engineering core is kept, and the theory claim is downgraded |

For P02/P05, "better than rules" is proposed as an increase of at least 10 percentage points in coverage under the same risk/width constraint, with paired uncertainty clustered by document. If the estimated uncertainty covers zero, record "cannot yet be decided", not "has no effect". Coverage and 90th-percentile width must also report sampling uncertainty. Whether a threshold has real task meaning must be explained on the exploration set and then frozen; the gate cannot be moved because the confirmation set failed.

## Sample budget comes before error-rate commitments

Even if zero failures are observed among accepted samples from a fixed pipeline that are independent and representative, at alpha=.05 getting the one-sided exact binomial upper bound strictly below .05 needs at least 59 independent audit units, because `1 - .05^(1/59) ≈ .0495`. If the error-rate target is changed to .01, at least 299 are needed. These are **ideal-condition budgets under zero failures**; they are neither evidence that a realistic sample size is sufficient nor a probability of success. Dozens of correlated fragments within one document cannot serve as dozens of independent units; cluster designs, nonzero failures, multiple targets, and drift all change the budget.

**The 120 local documents must be accounted for jointly.** Assume each contributes at most one accepted audit unit that can be treated as independent. Use 12–20 for exploration first, leaving 100–108; if the acceptance rate is exactly 50%, there are on average only 50–54 accepted units, short of 59. Reaching 59 even in expectation needs an acceptance rate of about 54.6%–59%, and that leaves nothing for training/development and does not guarantee that 59 will actually be accepted. The next design must list the document-ID budget for each of exploration, training, development, and the frozen risk audit. The same document cannot be used both to choose the acceptance rule and to certify that rule, and more fragments of the same document cannot pretend to be new independent samples. The independence/distributional representativeness of the original documents also does not follow automatically from the accounting. When the budget is insufficient, report the wider upper bound or the lower precision honestly; do not change the nominal standard after the fact to claim a pass.

P04's independent-cluster Hoeffding entry point is more conservative: with G=1, alpha=.05, equal-size clusters, and zero observed errors/zero drift, the radius for 120 clusters is about .1117, and the mean sharp bound at beta=.95 still equals B. At least 600 clusters are needed for this particular entry point to possibly be non-vacuous, and at least 937 clusters to possibly reach the .8B initial screening line. This only rules out non-vacuity of this entry point at the given scale; **it does not rule out every valid confidence bound, or all of P04**. If a tighter method is used instead, first prove its sampling and loss conditions and compare on the same target; see the revision of path 04.

## Sensitivity and the status of the gates

Width .05/.10/.20, acceptance rate .25/.50/.75, audit savings 10%/20%/30%, and deployment upper bound .5B/.8B/.95B can be reported in full as pre-listed sensitivity axes. There is only one main gate; one cannot pick the best-looking grid point from these as the ex ante success criterion.

These rules address "whether the next block of time is worth investing", and they do not replace the advisor's G0/G1. An explicit revision record is needed that reconciles the missing row-level material for the old model, the current requirement to build from scratch, and the strict training-from-scratch filter; one cannot claim the original decision gates are satisfied by relabelling the work as small trials.

# T1f：对五个候选 insight 查新

分支 `task/t1f`，目录 `research/t1f_novelty/`。需要联网检索，不需要 agent 答题。与 T1e 互相独立，可以同时做。

## 为什么做

首页 README 里有五条标成 🟡 的候选 insight。它们现在的依据只是"导师检索时没看到"。这一轮的任务是认真去找反例：找到有人做过同样的事，就是这一轮的成功。

## 要查的五条

| 编号 | 说法 | 什么算"已有人做过" |
|---|---|---|
| 🟡1 | 用输入的舍入区间精确计算金融问答基准里有多少题的答案定不到给定容差，并给出预测规则 | 有工作在 FinQA、TAT-QA、ConvFinQA 或同类基准上，按输入精度或条件数统计答案的确定性 |
| 🟡2 | 文档内的重复披露和加总关系几乎不能把答案重新确定下来 | 有工作用会计恒等式或重复披露收紧数值问答的答案范围，并报告效果 |
| 🟡3 | 模型不问时打印的位数与答案的真实精度无关；提醒数字经过舍入后，能给出正确的答案区间 | 有工作用精确的区间真值，测量语言模型报告数值精度或有效数字的能力 |
| 🟡4 | 不同模型、不同提示在 FinQA 上被判错的是同一批题，这些题经复核主要是参考答案错误和口径歧义 | 有工作在 FinQA 原始测试集上做逐题的跨模型判错重合分析，或给出判错的归因分类和比例 |
| 🟡5 | FinQA 的人工答案字段与程序执行值字段在约 6% 的题上互相矛盾 | 有工作报告过这两个字段的不一致率 |

## 做法

1. 每条至少用 8 组不同的检索词，覆盖 ACL Anthology、arXiv、Semantic Scholar、Google Scholar。把检索词全部记下来。
2. 必查的几处：FinQA、TAT-QA、ConvFinQA 的原论文和它们的被引文献；FinanceReasoning（ACL 2025）全文，尤其是它修订公开数据集的那一节和附录；DocMath-Eval、BizBench、FinanceMath；"Are We Done with MMLU"和同类的基准清洗工作；数值问答的评测容差讨论；XBRL 的舍入与计算规范。
3. 找到相关工作要读正文，不能只看摘要。
4. 每条给一个结论，三选一：**已有人做过同样的事** / **部分做过** / **读了正文仍未见**。"部分做过"要写清楚他们做了哪一部分，我们多出来的是什么。

## 交付

一页，一张表：

| 编号 | 结论 | 最接近的工作（题目、年份、链接） | 他们做了什么 | 我们多出来的是什么 | 把握（高 / 中 / 低） |
|---|---|---|---|---|---|

另附：全部检索词；读过正文的文献清单；每条最接近的三篇工作各一段摘录。

## 要注意

- 不要为了保住 🟡 而把相关工作说得离我们远。把某一条从 🟡 降下来，和确认它一样有用。
- 每个事实标来源层级：正文 / 摘要 / 二手。
- 只查不写：不改 README，不改短文初稿。结论回来后由导师改。
